# Psyche Game 项目流程与设计说明

## 1. 需求拆解
- 业务目标：构建“类似 4399 的游戏网站 + 攻略社区”。
- 核心功能：游戏入口展示、文章发布阅读、评论互动、作者数据分析。
- 工程要求：Docker 一键启动、真实数据库读写、完整前后端文档。

## 2. 设计之初完成内容
- 信息架构：定义“游戏广场 / 攻略社区 / 创作数据中心 / 管理后台”四大模块。
- 视觉方向：采用“苹果式简洁 + 高级动效”风格，控制留白、阴影和层次。
- 交互策略：重要路径全部带反馈（加载骨架、错误提示、按钮状态、空态）。

## 3. 技术方案决策
- 前端：Vue3 + Element Plus，保证开发效率与组件一致性。
- 后端：Spring Boot + Spring MVC + Security + Redis，保证可扩展和稳定性。
- 数据库：MySQL 承载核心业务，Redis 承载缓存与性能优化。
- 运维：Nginx 反代双后端实例，Docker Compose 统一编排。

## 4. 迭代实施顺序
1. 建立全栈容器化骨架（frontend/backend/mysql/redis/nginx/monitoring）。
2. 完成账号、文章、评论、收藏、分享统计等业务闭环。
3. 重构前端视觉与动效，形成游戏门户气质与移动端适配。
4. 增加作者数据分析与报表导出（POI Excel）。
5. 增加 WebSocket + Spring Task 实时推送社区指标。
6. 完成文档、测试与验收路径整理。

## 5. 质量与验收策略
- 通过 `docker compose up --build` 启动全链路。
- 验证真实数据 CRUD，不使用 Mock 代替核心流程。
- 重点验证作者端可见浏览量、点赞量、评论量与热度排行。
- 验证导出报表可下载，WebSocket 推送日志可观测。
